# 能力协商

[[Model Context Protocol]] 用一套**基于能力的协商系统**：client 和 server 在每个请求上声明所支持的功能。

## 怎么协商

- **client 侧**——在每个请求的 `_meta.io.modelcontextprotocol/clientCapabilities` 里带上能力（如 sampling 支持、elicitation 处理）。见 [[_meta 元数据]]。
- **server 侧**——通过 `server/discover` RPC 通告支持的协议版本、能力和身份；client **MAY** 在任何其他请求前调用它做前置能力发现（本版新增，server **MUST** 实现）。server 声明如工具支持、资源订阅、prompt 模板。
- 双方 **MUST** 在整个交互中尊重已声明的能力；额外能力可通过协议扩展协商。
- server **MUST NOT** 依赖 client 未声明的能力——若处理请求需要 client 没带的能力，server **MUST** 返回 `MissingRequiredClientCapabilityError`（`-32021`），在 `data.requiredCapabilities` 列出缺失项。

## 每个能力解锁特定功能

能力按请求解锁具体协议功能：已实现的[[MCP 服务器原语|server 功能]]必须在 server 能力里通告；接收资源更新通知要开 `subscriptions/listen` 流；[[MCP 服务器原语|Tool]] 调用要求 server 声明 tool 能力。

常见叫法：能力协商、capability negotiation、按能力协商、server/discover、能力发现、declared capabilities。
