# 客户端-主机-服务器架构

[[Model Context Protocol]] 采用 client-host-server 三方架构。一个 host 可运行多个 client 实例，每个 client 与**恰好一个 server** 保持 1:1 关系。这一架构让用户跨应用集成 AI 能力，同时维持清晰的安全边界与关注点隔离。

## 三方职责

- **Host（主机）**——容器与协调者：创建管理多个 client 实例、控制连接权限与生命周期、强制安全策略与同意要求、处理用户授权决策、协调 AI/LLM 集成与 sampling、跨 client 聚合上下文。
- **Client（客户端）**——host 创建的连接器，与一个 server 1:1 通信：每个请求附带协议版本与能力、双向路由消息、管理订阅与通知、维持 server 间安全边界。
- **Server（服务器）**——提供专门上下文与能力：通过 MCP 原语暴露 [[MCP 服务器原语|resources/tools/prompts]]、独立聚焦运作、可为本地进程或远程服务、必须尊重安全约束。

## 关键安全设计

一条核心设计原则：**server 不能读取整个对话，也不能「看进」其他 server**。完整对话历史留在 host，每个 server 只收到必要的上下文，跨 server 交互由 host 控制，host 进程强制安全边界。这与[[无状态协议]]性质配合——每个请求自包含。

常见叫法：client-host-server、客户端-主机-服务器、三方架构、host/client/server、MCP 架构、主机-客户端-服务器模型。
