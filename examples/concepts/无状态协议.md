# 无状态协议

[[Model Context Protocol]] 2026-07-28 版是一个**无状态协议**：处理一个请求所需的全部信息都在请求本身。server 独立处理每个请求，不从先前请求推断状态——即使是同一连接或流上的请求。

## 具体规则

- server **MUST NOT** 依赖同连接的先前请求建立上下文（能力、协议版本、client 身份）；每个请求在 [[_meta 元数据|`_meta`]] 里自带这些。
- 跨请求的状态（长任务、应用级句柄）**MUST** 由 client 每请求传一个显式标识符来引用。
- 开放连接（如 STDIO 进程）**不是**对话或会话——client 可在同一传输上交错互不相关的请求，server 不得把连接/进程身份当作会话连续性的代理。
- `subscriptions/listen` 这类长连接仍是请求/响应，响应只是一条开放的通知流，其状态作用域是请求本身而非底层连接。

## 本版如何变成无状态

这是 2026-07-28 相对上一版（2025-11-25）的重大变更（见 [[MCP 关键变更]]）：移除了 `initialize`/`notifications/initialized` 握手，也移除了协议级 session 和 `Mcp-Session-Id` 头。取而代之，每个请求在 `_meta` 里携带 [[能力协商|协议版本和 client 能力]]。

常见叫法：无状态协议、stateless、无状态化、去 session、自包含请求、每请求自带上下文。
