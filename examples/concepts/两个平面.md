# 两个平面

[[AWS Agent Registry]] 内部跨两个互补平面运作，干净地分离「治理」与「发现」两种关注点。

## Governance Plane（治理平面）

已注册资源的**权威存储**，不论其生命周期状态（草稿、待审、已批、已弃都在）。管理员在这里配置塑造资源管理方式的规则：

- **合规与安全信号**——追踪资源是否过安全审查、是否满足监管、是否有已知风险的元数据。
- **发现策略**——基于权限的搜索规则，按角色/团队控制谁能看到哪些资源。
- **自定义元数据 schema**——组织特定字段（如 cost center、数据分级、SLA tier），标准化资源描述。

## Discovery Plane（发现平面）

消费者日常交互的界面，只呈现**通过组织审批门槛**的资源：

- **策展而非全量**——只有 admin 或 curator 批准的记录出现；草稿、被拒、影子资源对消费者不可见。
- **为规模而建**——支持高吞吐查询，agent 和开发者可程序化搜索而不触发限流。
- **语义 + 词法搜索**——按意图（「find me a tool for ticket routing」）或精确名查找。
- **信任信号而非治理细节**——呈现摘要化的合规/安全指标，框定为「是否该用」的决策依据，而非原始治理数据。

## 为什么分两个

管理员通过 Governance Plane 获得全面可见性和策略控制；消费者通过 Discovery Plane 获得快速、受治理、只见「可用」资源的搜索体验。两侧由[[四种角色]]分别对应。

常见叫法：两个平面、Governance Plane、Discovery Plane、治理平面、发现平面、双平面架构、治理面与发现面。
